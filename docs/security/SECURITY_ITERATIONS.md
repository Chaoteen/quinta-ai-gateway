# 近期安全迭代与验收边界

## 2026-11-16 本批应用改动

- 平台采购管理仅最高管理员可读，所有写入要求近期MFA二次验证；二次验证绑定当前账号，并拒绝未来时间戳；Passkey预验证标记一次性消费且绑定账号。
- 供应商账号只绑定已核验官方HTTPS源站及对应协议，拒绝私有/伪装域名、订阅路径和SDK路径误填。不将API Key明文复制到新采购模块。
- 绑定后的端点与协议发生变化时阻止后续调用；供应商暂停、账号暂停或授权到期后阻止新请求；禁止直接复制绑定渠道。
- 采购金额用精确十进制转换整数，报价与付款分离；付款流水幂等且累计不能超额；业务与审计在同一事务写入。
- 新表及渠道归属字段使用兼容迁移；本批不自动绑定旧渠道、不改变现有余额、不自动向上游转账。

## 后续优先级（尚未宣称完成）

P0：全平台管理员强制MFA的分阶段启用与应急恢复；生产上游凭据KMS托管及轮换；独立不可变备份与恢复演练；云安全组、堡垒机和主机防火墙联动。实施前应确认恢复通道及同机其他服务依赖，不能直接关闭共享端口或更换运行凭据。

P1：集中防篡改审计与告警、应用/数据库/备份权限隔离、依赖及镜像持续扫描、全租户越权回归、上传及出站请求的SSRF专项、支付回调和异步任务异常恢复。应用层审计表不能替代独立防篡改审计存储。

P2：等保定级边界、备案材料与制度、第三方测评及整改闭环。安全代理进程、WAF购买记录或代码扫描通过都不能单独证明达到等保二级。

本批测试以隔离SQLite和浏览器模拟接口为主；需继续验证MySQL/PostgreSQL/Redis多实例，以及五家官方真实账号的协议、配额、费用与授权范围。源代码公开不包含真实生产凭据；不以隐藏漏洞或隐藏署名代替修复和履行许可证。

## 2026-11-16 第二批：缓存一致性与采购关联保留

调用检查以数据库当前渠道及供应商关联为准，不能根据缓存中的supplier_account_id=0直接放行。新绑定、暂停、授权到期以及数据库中端点/协议变更，即使本实例仍持有旧渠道缓存，也必须检查最新状态；记录不存在、绑定不一致或查询失败时拒绝调用。当前实现每次检查读取数据库，后续性能优化不得丢失这个授权边界。

单条、批量、按状态和清理禁用渠道均通过同一事务删除流程：锁定候选渠道，检查渠道归属字段及实际供应商账号关联，只删除未绑定记录并同步清理abilities。涉及绑定渠道时整批拒绝，不删除其他选中渠道；保留合同、账单和付款关联。租户清理只影响本租户记录。

新增隔离测试覆盖旧未绑定缓存、新绑定后暂停/到期、数据库端点变更、四种删除入口的整批回滚，以及租户作用域。没有启动真实多节点Redis环境，不能把这些回归测试表述为已完成多机压力验收；未调整端口、管理员认证器或密钥。

## 2026-11-16 第三批：认证恢复与密码登录边界

恢复码使用改为数据库条件更新，只有成功把未使用记录标记为已使用的请求才能通过验证；并发重放不能重复成功。新增同步并发回归，确保多个请求已读取同一未使用恢复码后只有一个更新成功。使用GORM和参数化布尔值，不引入数据库专属语法；实测仍为隔离SQLite。

密码登录读取两步验证配置失败时返回失败，不能降级为无两步验证登录。密码验证后的待验证会话有效期为五分钟，拒绝缺少时间戳、未来时间戳及过期挑战；完成第二步前重新检查账号启用状态。新密码挑战清除旧会话身份和近期二次验证授权，登录完成也清除旧挑战及授权，防止跨登录继承。

本批未开启全局强制MFA，未改变生产管理员绑定或恢复码；旧的待验证挑战需要重新输入密码。第三方OAuth、Passkey、访问令牌与既有登录会话的统一强制策略仍需另行覆盖，不能据此宣称已实现所有认证入口的强制MFA或完整的会话撤销机制。

## 2026-11-17 第四批：交互登录统一两步验证

密码、统一OAuth、保留的旧OAuth/微信/Telegram入口和Passkey身份验证完成后统一经过setupLogin：重新读取当前用户状态和本地TOTP配置。账号已启用TOTP时只返回限时挑战，必须通过认证器或恢复码才可建立会话；第三方身份验证或Passkey成功本身不跳过账号已启用的TOTP。查询失败或账号已禁用时拒绝建立新会话。仅第二步验证完成可调用completeLogin，不重复保存中间会话Cookie。

默认前端补齐OAuth回调、微信与Passkey的挑战跳转，进入OTP前清除旧的本地用户和uid，避免把挑战响应当成用户资料。经典主题同步补齐对应跳转。绑定已有第三方账号的流程不当作登录挑战。

隔离测试覆盖真实Cookie往返、挑战阶段无登录身份、恢复码完成后建立身份、最新禁用状态和查询失败；默认前端浏览器模拟验证OAuth→恢复码→控制台闭环。两种前端构建通过。未用真实第三方OAuth账号或硬件Passkey做端到端验收；访问令牌、已有会话撤销与未绑定管理员的全局强制策略仍属后续工作。本批不启用全局强制MFA，不修改生产认证器绑定。
