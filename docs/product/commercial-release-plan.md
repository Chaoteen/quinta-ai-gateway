# 企业商用交付计划与验收边界

本计划以 2026-11-09 产品基线为准；本文件不表示平台已通过商业上线验收。

## 已进入验证的本批改动

1. 统一单次额度转换边界，阻止浮点/Decimal 越界回绕成负数；限制图片数量、跨协议输出预算、任务时长及非有限计费倍率。合法的结算差额仍允许有符号数值，钱包累计余额和单次消费额度不混用同一上限。
2. 增加平台统一收款模式：订单保留客户企业归属，单独冻结收款企业、商户身份、币种和报价。人民币政策按客户企业版本化，客户不能借用其他收款账户，平台财务审核银行流水；客户自己的企业管理员不能审核平台到账。
3. 增加可见的许可与对应源码页面，保留原有署名，补充原项目链接和修改说明。继续按 AGPLv3 公开交付，不宣称已经取得商业闭源授权。

## 待完成后才可验收的业务闭环

| 业务 | 验收结果要求 | 本批边界 |
| --- | --- | --- |
| 企业账户 | 申请、平台审核、单一企业归属、公司共享资金账户、内部应用归因；个人资产不自动混入企业 | 当前租户/角色管理不是完整企业开户与共享钱包，尚不可按完整功能验收 |
| 卡券 | 批次发放、作用域、过期、核销幂等及审计；优惠/补贴与赠送余额分账 | 已有额度/订阅券及并发测试；政府补贴月度预占、申报和到账流程尚未接入 |
| 计费 | 版本化报价、预留/结算、充值/消费/退款统一账本、并发与断连处理、月度对账 | 本批保护转换边界并支持平台收款快照；入账流水不是完整消费与现金账本 |
| 支付 | 支付产品审核、真实商户配置、验签/查单、重复回调、异常订单恢复、原路退款 | 尚未开通商户 API，不启用真实在线支付；银行模式需真实收款账户及政策配置后联调 |
| 发票 | 发票资格口径、抬头快照、金额占用、财务审核、真实税务开票、私密交付及红冲 | 已有申请/审核/人工登记基础；自动开票、消费资格账本及私密文件存储尚未完成 |

## 平台公司统一收款配置

测试并审核配置后才可设置 `PAYMENT_COLLECTION_MODE=platform` 和显式 `PLATFORM_TENANT_ID`。收款账户属于平台企业，订单 `tenant_id` 始终表示客户企业，`receiving_tenant_id` 表示收款企业。不要把客户付款银行账户当成支付宝/微信的收款商户。

需由可信管理流程创建收款账户及客户的 `TenantFundingPolicy`；每种币种使用明确的额度换算规则，不自动换汇。首次只接受人民币。未配置账户、价格或收款主体时拒绝创建订单。旧独立收款订单按其原有接收身份处理，不重写历史资金归属；旧全局充值入口仍受保护。

支付宝/微信未开通时，不创建模拟支付成功记录。开户银行可以咨询对公账户、结算支持和银行收单产品；直接商户接入通常由支付平台完成商户及支付产品审核。费率、结算周期、退款和提现规则以审核及签约条款为准。

## 发布与实际联调

- SQLite/MySQL/PostgreSQL 分别验证迁移、并发核销及重复回调。
- 使用隔离测试环境执行资金与发票测试，不用生产余额做破坏性测试。
- 每批发布保留源码提交、测试结果、数据库备份和回滚版本。
- 有页面、模型或接口不代表业务闭环完成；真实支付和开票验收需要公司完成对应服务的开通与授权。
