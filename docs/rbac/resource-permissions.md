# 资源动作 RBAC：实现与边界

角色：root（平台），supplier_admin（供应商），distributor_admin（分销商），enterprise_admin（企业），user（个人）。保留 tenant_admin / organization_admin / finance / ops / auditor 的旧接口策略以兼容现有账号，后续逐项迁移，不能把旧 tenant_admin 自动视为新的企业角色。

动作：view 可见/读取、use 使用、create 创建、operate 业务操作、update 修改、delete 删除。所有权限与资源归属相交；前端隐藏按钮不是服务端授权。common/resource_permissions.go 是新角色默认矩阵。未知角色、资源、动作拒绝。当前不开放任意自定义通配权限。

## 已接入

- GET /api/rbac/self：本人默认矩阵；GET /api/rbac/roles：root 查看新角色矩阵；POST /api/rbac/assign：root 安全验证后分配业务角色。
- /role-permissions 平台页面展示矩阵，选择用户 ID 和角色后安全验证；不能通过该接口创建 root。
- 分配只在现有独立且有效的租户内生效；tenant_id<=1 的共用个人注册账号拒绝分配。不会隐式搬迁已有资金、Key 和订阅。目标不能是自己或 root。
- 角色变更与 RoleAssignmentAudit 在同一个事务；失败全部回滚。auth_epoch 递增并撤销个人管理令牌，原浏览器需重新登录。客户推理 Key 不自动删除。
- 新角色使用管理员数值仅兼容旧控制器；authHelper 对这些角色额外执行显式路由白名单，未知接口拒绝，不能继承全部旧 Admin 接口。RootAuth 始终保持 root 限制。
- 供应商仅可对本租户渠道执行当前白名单内的创建、读取、修改；渠道控制器已有租户归属校验。批量、删除、凭据读取、OAuth、Ollama 管理等未委派。
- 企业/分销商的成员列表、详情、创建、资料修改和删除使用现有租户边界。委派资料修改不能改定价分组或重置密码；角色提升、额度调整、登录绑定、安全凭据重置仍未委派。
- 自用 API Key、账单、付款申请、发票申请、卡券核销、订阅购买继续由原控制器校验本人/租户归属；付款确认和发票签发不向业务管理员开放。
- 前端为新角色显示独立菜单；供应商渠道页仅显示委派操作，成员页隐藏遗留管理动作。平台采购后台 /suppliers 依旧仅 root，这是平台采购功能，不等于供应商门户。
- 审计导出加入角色分配记录，旧断点只添加新来源，不重置已有游标。SLS 尚未配置，不能声称已实现云端审计。

## 仍未完成的业务闭环

矩阵中的供货报价、分销售价、模型发布审核、分销卡券发放需要专门的范围模型与接口，目前尚未接入；不能仅按矩阵某项为 true 宣称功能可用。企业账单/付款/发票当前自用接口仍按本人限制，不会因为企业角色自动聚合全企业；企业汇总、统一资金账户和财务分工还需实现。财务证据删除不因普通业务管理员存在而开放。

本轮是可执行的 RBAC 基础与当前接口隔离，不是全部商业角色业务的验收完成。相关未完成入口保持隐藏/拒绝，禁止临时放宽 RootAuth 来模拟闭环。旧角色体系的全面逐动作迁移和 classic 前端的新角色体验也未完成。

## 验证

Go common/model/middleware/router/controller 测试包含动作隔离、未知权限、角色分配拒绝、事务审计失败回滚与原边界回归。scripts/test_export_security_audit.py 验证导出恢复。生产账号不用于破坏性测试，不自动提权或创建商业数据。
