# 可配置与委派 RBAC 验收规范

## 用户需求

平台管理员配置平台、供应商、分销商、企业管理员的资源动作权限；各类型主管理员在自己的租户内，为用户分配平台准许的角色。动作分别为可见、可用、创建、操作、修改、删除，不能用菜单隐藏替代接口授权。

## 本轮契约

1. 平台 root 固定拥有全局管理权，不能通过角色配置接口创建 root、修改自己的 root 身份或将平台专属权限委派给租户。
2. 供应商、分销商、企业三种管理员类型分别有可配置的权限上限；平台可在既有安全上限内授予或收回动作，决定该类型主管理员是否可以创建和分配租户角色。默认关闭委派。
3. 主管理员指平台直接任命、没有绑定下级自定义角色的业务管理员。其可创建诸如“企业财务”“模型运营”“只读审计”的租户角色，只能授予本类型当前上限以内的权限。
4. 自定义角色归属固定 tenant_id 和管理员类型，不能通过编辑迁移归属。仅允许独立、有效租户（ID>1）。跨租户、跨类型、自我分配、修改同级主管理员、给员工授予委派权限均拒绝。
5. 本轮支持一级委派：平台→业务主管理员→自定义成员角色。成员不自动获得继续授权的能力；不存在可递归的角色继承，因此不能创建授权环。
6. 成员实际权限 = 自定义角色勾选权限 ∩ 平台当前上限；主管理员为该类型当前上限。后端每次请求实时读取，不缓存权限决定。收回上限、修改或停用角色，从下一次授权检查生效；不宣称中断已开始的请求。
7. 授权配置与审计同事务；审计失败则回滚。版本冲突拒绝覆盖。给用户分配、撤销、平台重新任命时递增 auth_epoch 并撤销个人管理令牌，原浏览器重新登录。角色配置变化通过实时鉴权收紧，不必等待用户重新登录。
8. 密钥创建、使用/展示、修改、删除分开；POST 批量删除按 delete 判断；个人聊天配置快捷入口也必须经过密钥创建权限检查。模型调用权限独立于密钥管理，旧调用 Key 不能绕过 model_calls.use。
9. 平台采购、真实收款确认、发票签发等平台能力不向租户开放；供货报价/分销定价的独立业务闭环不在本轮授权引擎中伪造。现有旧角色兼容策略保留，新增角色不继承其全部管理员接口。
10. 新前端按实际权限显示入口与按钮；业务工作台不主动请求无权访问的接口。后端实时拒绝，前端在授权页操作后或窗口聚焦/30秒同步更新展示。classic 暂不提供新增角色编辑体验，但使用同一后端鉴权。
11. 撤销自定义角色恢复为普通用户；停用角色移除业务权限。两者不等于封禁账号，也不删除历史财务记录或客户密钥；账号封禁为独立操作。
12. 平台权限上限按管理员类型全局配置，自定义角色按租户隔离。本轮没有多角色合并、任意层级委派、部门级继承或给每个租户单独覆盖平台上限的能力。

- model/rbac_workspace_test.go：默认关闭委派、上限校验、跨租户/自我/同级保护、审计失败回滚、实时撤权、撤销恢复普通用户、并发版本冲突。
- router/rbac_workspace_test.go：真实注册路由的授权配置/委派生命周期、旧会话失效、接口动作拒绝、个人快捷入口拒绝、旧模型 Key 的实时调用限制。仅使用内存或显式一次性测试库。
- scripts/test_export_security_audit.py：新增来源的断点升级与既有游标保留，持久化失败重试；SLS 尚未开通，远端接收不属于已通过项。
- 前端浏览器测试：平台配置、企业角色创建/分配前身份验证、只读角色无写入按钮、跨租户错误、手机布局。模拟接口验证交互；生产仅做只读访问，不提权、不付款、不消费模型额度。

## 使用顺序

1. 平台 root 在“租户管理”确认企业拥有独立有效租户；普通注册用户仍是个人账号，不因注册自动拥有企业管理权限。不要只改用户 tenant_id 来搬迁已有资产。
2. 进入 `/role-permissions`，选择管理员类型，按需要勾选平台授权上限并开启委派，经过认证器/Passkey验证保存。此处上限按类型作用于所有该类租户。
3. 对已经属于目标租户的用户，使用用户 ID“设为此类型的主管理员”；任命会要求重新登录。
4. 该主管理员登录同一站点，在“角色与权限”选择自己的租户角色或新建，例如只读财务；勾选允许的资源动作并验证保存。角色名称支持至多128个UTF-8字节。
5. 输入本租户成员用户 ID、选择角色、验证分配；成员重新登录。角色停用保留审计和历史，不删除资金；撤销角色恢复个人用户身份，不能当作封禁操作。
6. 平台收回上限、管理员修改/停用角色后，下次服务端授权即生效；界面聚焦或30秒刷新，进行中的请求不被承诺中断。

未配置认证器/Passkey时必须先完成绑定；不能为了测试绕过安全验证。所有账号使用同一登录入口，菜单由真实角色和权限控制。


## 本地复现

后端：使用项目已要求的 Go 工具链执行 `go test ./common ./model ./middleware ./router ./controller ./service`。审计：`python scripts/test_export_security_audit.py`。

前端：在 `web/default` 设置 `VITE_BASE_PATH=/quinta`，执行 `bun run build:check`。已有 Playwright 环境运行 `python scripts/test_rbac_ui.py`；可用 `--browser-executable` 指向现有浏览器。脚本自建仅监听127.0.0.1的临时静态服务，全部API均为模拟，不访问生产。截图默认放在 `.audit-tools/rbac-ui`，可以用 `--artifact-dir` 修改输出目录。不得将脚本改成生产写入测试。
