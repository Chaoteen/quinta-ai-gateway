# 开发约束与验证

四个工程技能安装在本机 Codex skills 目录：tdd、code-review、diagnosing-bugs、domain-modeling。来源 mattpocock/skills，固定提交 bbadaa631c37af594e5a05c9cefacd9956136b18，保留 MIT 声明与 SOURCE.json，不自动追随 main。它们是开发方法，不是漏洞扫描引擎或安全认证。

按需求使用：权限/计费等高风险变更先写可失败的行为测试；缺陷先复现精确症状；审查分别检查项目规范和需求完成度；业务术语有歧义时维护词汇，不重复追问已确定的产品设计。

仓库 AGENTS.md、用户授权和安全边界优先。技能里的 Bash、包管理、测试示例需按 Windows/PowerShell、Go 与 Bun 适配；不能运行不兼容命令、扩大权限或把测试指向生产。没有 .git 时，以 GitHub 固定提交/真实比较替代本地 diff，明确证据来源。

每个安全迭代必须有简短需求、已完成/未完成映射和可执行验证。接口、模型调用、审计、会话失效是本轮关键验证入口，不能只测矩阵函数。跨租户、提权、撤权、并发和异常回滚必须作为反例；通过测试不等于完成等保或独立安全审计。

现有 commercial-security.yml 执行后端测试、依赖/秘密扫描、前端构建及数据库测试。本轮增加一次性 MySQL/PostgreSQL 的 RBAC 隔离和并发版本测试。原始扫描、浏览器认证数据、ECS 配置和凭据只存私有目录，不提交公共仓库。

不得将“已安装技能”“存在权限表”写成“功能闭环已完成”。发布报告需区分模型测试、路由测试、模拟浏览器验证、真实网站只读验证和未完成验证。
