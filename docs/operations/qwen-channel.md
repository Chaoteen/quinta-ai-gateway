# Qwen 模型接入与验证

本平台可以将千问 AI 平台的 Qwen 模型接入“模型体验”和客户 API。一个上游 Key 可以有多个模型的调用权限，但每次请求仍必须指定准确的模型名称；模型列表不等于所有模型都已经过实际调用验证。

## 管理员配置渠道

在“渠道”页面新增渠道，填写：

| 配置项 | 值 |
| --- | --- |
| 类型 | Ali / 阿里云，渠道类型编号 17 |
| 接口地址 | `https://maas.qianwenaiapi.com` |
| 模型 | `qwen3.8-max` |
| 测试模型 | `qwen3.8-max` |
| 分组 | `default` |
| 租户 | 明确选择拥有这项上游资源的租户 |
| Key | 通过后台私密录入；不要写进源码、文档或 GitHub |

注意：类型 17 的适配器会自动拼接 `/compatible-mode/v1/chat/completions`，渠道的接口地址只填写上表中的域名。它和普通 OpenAI 客户端中的完整 Base URL `https://maas.qianwenaiapi.com/compatible-mode/v1` 填法不同，不能混用。

以上地址属于千问 AI 平台按量计费接口。阿里云百炼、其他地域和 Token Plan 的凭据、地址应分别核实，不要直接替换域名试发真实 Key。

## 设置价格

2026-11-12 联调采用官方公开参考价：输入 12 元／百万 Token、输出 36 元／百万 Token，隐式缓存命中 1.5 元／百万 Token。未额外设置销售加价；这是一套联调价格，正式销售前应确认平台销售定价和上游合同价。

当前平台配置的额度换算值为 `Price=7.3`、`USDExchangeRate=7.3`，并不是实时汇率。按照现有倍率计费方式，模型配置为：

- `ModelRatio["qwen3.8-max"] = 12 / 7.3 / 2`
- `CompletionRatio["qwen3.8-max"] = 3`
- `CacheRatio["qwen3.8-max"] = 0.125`

修改配置时合并这一个模型的条目，保留其他模型价格。不应开启“允许未配置价格模型”来绕过计费。显式缓存的创建、命中和其他付费工具需要单独核实实现，不能据此宣称已经完整支持其计费。

## 用户如何使用

1. 登录后打开“模型体验”。
2. 选择 `default` 分组和 `qwen3.8-max`。
3. 在输入框填写问题，再点击“发送”。模型体验通过登录会话调用，不要求预先创建客户 API 密钥；账户仍需有可用额度。
4. 如需在外部聊天工具或自己的程序中使用，先在“API 密钥”页面创建客户密钥，再使用网关的地址接入。客户密钥与上游 Key 是两种不同凭据，不要把上游 Key 发给客户。

模型由后端按分组和租户提供。没有可用渠道时，页面应显示无可用模型并阻止发送，不应默认假设存在 GPT 模型。

## 联调验证与赠送额度

已完成上游模型列表检查、中转站非流式请求和真实网页流式问答验证；实测模型为 `qwen3.8-max`。其他模型需要逐项验证后再开放。

经用户明确授权的 1 元测试额度通过现有 TOKEN 卡券生成、核销和额度入账服务发放。在当前换算配置下对应 68,493 个内部额度单位，显示约为人民币 1.00 元。这些单位不是模型 Token 数。

赠送记录包括卡券批次、核销记录和唯一来源的额度入账流水，不创建付款订单，也不产生基于真实付款的开票额度。普通新注册账户的初始余额仍为 0。

凭据和账户余额属于服务器运行配置，不提交到公开仓库。复用其他项目的上游 Key 会共同消耗同一上游账户的额度；平台独立用量日志不能替代上游账单。正式运营宜使用单独业务空间或专用 Key 便于限额、撤销与对账。
