# 发票管理

发票用于客户报销和财务核对。你的公司是销售方，企业租户是购买方；企业管理员不能代表销售方审核和开具发票。

2026-11-09 已确认：平台具备一般纳税人主体，可以开具普通发票和增值税专用发票，目前没有对接开票软件。建议先由平台受理申请，财务通过电子税务局真实开票，再登记票号及交付文件；后续再接开票服务商 API。

当前代码仍处于开发阶段：已完成部分申请与人工登记保护，没有自动调用税务系统，也没有完整的消费可开票台账、退款红冲及私有文件交付。不能把上传一个 PDF 视为系统已经自动开具了税务发票。

## 适用场景

- 企业客户按已确认的服务消费申请发票。
- 按月核对模型和智能体服务账单，再申请发票。
- 财务人员审核发票资料和开票状态。

## 发票信息

申请发票前，请准备：

- 发票抬头。
- 纳税人识别号。
- 在可开票范围内的申请金额，人民币精确到分。
- 接收邮箱或邮寄信息。
- 对应服务消费及付款记录。

抬头、税号和购买主体需要核对。个人抬头仅支持普通发票；企业抬头可按资质选择普通或专用发票。具体商品名称、税收分类编码、税率和含税口径由平台财务确认，不从竞品复制固定税率。

## 建议的客户流程

1. 在费用中心查看“可申请、申请中、已开票、红冲处理中”金额及明细。
2. 选择服务周期、可开票明细、抬头和票种，查看申请金额及明细后提交。
3. 财务核对合同、购买主体、资金与消费来源；有问题则拒绝并说明原因。
4. 财务在电子税务局开票，或在后续 API 接入完成后发起自动开票。
5. 确认真实开票结果后交付票据，客户可以查看票号、日期及下载文件。

这五步是目标流程，当前系统未完整实现按消费周期选取明细和自动开票。

## 金额原则

- 充值余额、消费金额和可开票金额分别展示。建议采用按已确认服务消费开票，不把未使用充值余额直接当作已消费金额。
- 赠送额度和优惠券不作为客户实付现金；合同折扣、部分退款和历史开票必须能追溯到原消费明细。
- 政府补贴单独记录“客户支付、平台减免、政府应收及到账”。补贴是否构成交易对价、对谁开票以及发票金额，由具体补贴政策、合同和财务税务判断确定；不能简单认为只对客户支付的 70% 开票，也不能默认按 100% 开票。
- 模型费用和智能体订阅服务费分别记录，再按同一主体、币种及财务认可的规则合并开票，避免套餐权益和其内部模型消耗重复计入发票。

上述消费台账尚未接入当前申请接口。当前接口只校验已付款订单及其已占用申请金额，不能单独据此开放商用自助开票。

## 状态说明

- 待审核：申请已提交，等待财务处理。
- 审核通过：资料与申请已审核，尚未开票。
- 已开票：发票已开具。
- 已拒绝：资料不完整或金额不匹配。

## 对账建议

发票金额应与支付订单、账单记录一致。若存在差异，请先完成账单核对。

已开具数电发票后的退款或更正，需要按规则进入红字发票流程，不能仅删除记录或改成“已取消”。[国家税务总局数电发票公告](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5236067/content.html)

## 接入方案

| 阶段 | 交付方式 | 启用条件 |
| --- | --- | --- |
| 首批企业 | 财务在电子税务局开票，平台申请、审核及登记真实票据 | 完成消费可开票台账、权限、金额核对、私有文件及退款协同验收 |
| 自动化 | 通过开票服务商 API 开蓝票、查询结果、交付和红冲 | 完成服务商签约、主体授权、测试、异步幂等和每日对账 |
| 后续评估 | 自建税企直连 | 按业务规模和当地接入条件另行评估，不作为第一版依赖 |

优先比较已有公开平台能力的供应商，不预先承诺价格、接口权限或认证方式：[百望开放平台](https://e.baiwang.com/)、[诺诺合作与开放能力](https://www.jss.com.cn/nuonuo/web/teamwork/teamIndex/index.html)。选型时要求演示普票/专票、红字确认及红票、查询补偿、额度不足处理、原始电子文件、审计导出和沙箱测试。

## 参考产品

- [硅基流动发票说明](https://docs.siliconflow.cn/docs/userguide/faqs/invoice)：可借鉴抬头、票种、已消费金额申请及历史下载流程。这是该平台规则，不直接代替本平台财务确认。
- [非线智能模型广场](https://nonelinear.com.cn/static/models.html)：公开页面提供模型搜索、模态及价格等筛选、接入代码入口；完整模型与折扣信息需要登录。本次未核验其登录后的财务界面。
- [OpenRouter 企业账户](https://openrouter.ai/docs/cookbook/administration/organization-management)及[用量分析](https://openrouter.ai/blog/announcements/activity-dashboard/)：可借鉴共享企业余额、按 Key/应用/模型归因以及从汇总追查请求明细，不把海外账单收据当作中国增值税发票。

平台界面建议分为模型与智能体、API Key、用量、费用中心。费用中心集中呈现充值、套餐、月账单、补贴、发票与退款；申请表展示明确字段标签、金额明细、提交中状态和失败原因，不仅显示一个总余额。
